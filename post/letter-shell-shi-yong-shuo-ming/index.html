Letter Shell 使用说明

2026-09-14

1. 工程中的 Shell 组成

本工程将 Letter Shell 移植到 STM32F407，并使用 USART1 作为交互串口。

文件 作用
app/main.c 创建 Shell 对象，配置读写接口，并在裸机主循环中运行 Shell。
driver/console/console_usart.c 配置 USART1，提供发送函数和接收回调注册函数。
app/commands/helloworld.c 实现helloworld 示例命令。
app/commands/add.c 实现add 示例命令。
third_lib/lettershell/shell_cmd_list.c 使用命令表方式集中注册 Shell 命令。
third_lib/lettershell/shell_cfg.h 配置 Shell 功能。

串口参数为 115200-8-N-1。使用串口助手连接开发板后，发送命令并以回车或换行结束即可。

2. Letter Shell 源码移植

Letter Shell 的核心源码已从源码包的 src 目录移植到本工程的 third_lib/lettershell 目录。它本身与具体 MCU、串口和 RTOS 无关；本工程通过 main.c 中的读写函数，将它连接到 STM32F407 的 USART1。

2.1 移植文件说明

文件 是否加入 Keil 编译 作用
shell.c 是 Shell 核心，实现输入编辑、命令匹配、参数解析、历史命令和执行流程。
shell.h 否 定义Shell、ShellCommand、核心函数和命令注册宏。
shell_cfg.h 否 配置 Shell 的功能开关、历史记录数和缓冲区大小。
shell_ext.c 是 提供 Shell 的扩展参数处理功能。
shell_ext.h 否 声明扩展功能接口。
shell_cmd_list.c 是 定义内置命令及本工程的用户命令表。

shell.c、shell_ext.c 和 shell_cmd_list.c 必须加入 Keil 工程并参与编译。头文件不需要单独编译，但必须能被编译器找到。

2.2 Keil 配置

当前工程的 Keil 配置已经包含以下头文件路径：

..\firmware\cmsis\core
..\firmware\cmsis\device
..\firmware\driver\inc
..\driver\console
..\app
..\third_lib\lettershell

从零移植时需要完成以下步骤：

  1. 复制上述 Letter Shell 文件到工程目录。
  2. 将 shell.c、shell_ext.c 和 shell_cmd_list.c 加入 Keil 工程。
  3. 将 third_lib/lettershell 加入 Keil 的头文件搜索路径。
  4. 在 shell_cfg.h 中按裸机或 RTOS 场景调整配置。
  5. 在应用代码中实现 shell.read 和 shell.write 对应的硬件适配函数。
  6. 调用 shellInit() 初始化实例，并在主循环或独立任务中调用 shellTask()。

2.3 本工程选择的命令注册方式

shell_cfg.h 中的配置为：

#define SHELL_USING_CMD_EXPORT 0

值为 0 表示使用命令表方式。命令函数实现后，需要在 shell_cmd_list.c 中先写 extern 声明，再在 shellCommandList[] 数组中使用 SHELL_CMD_ITEM() 注册。

这种方式适合 Keil 裸机工程，命令位置明确、无需修改链接段配置。将该宏改为 1 后可使用 SHELL_EXPORT_CMD() 分散注册命令，但必须确保 Keil 链接器正确收集 shellCommand 段；当前工程不建议直接切换。

2.4 Shell 与硬件的连接关系

串口助手 -> USART1 接收中断 -> 接收回调 -> shell.read -> Letter Shell
Letter Shell -> shell.write -> USART1 发送函数 -> 串口助手

因此，移植到其他串口、USB 虚拟串口、网络或蓝牙时，不需要改动 Shell 核心源码；只需替换 shell.read、shell.write 和底层通信驱动。

3. main.c 逐步说明

当前 app/main.c 是 Shell 的裸机入口。它完成三件事：初始化硬件、把 Shell 与串口连接、在死循环中驱动 Shell。

3.1 头文件与全局对象

main.c 开头的核心代码如下：

#include "console_usart.h"
#include "shell.h"

static Shell shell;
static char shell_buffer[512];

extern void board_lowlevel_init(void);

static volatile uint8_t rx_data;

各项作用如下：

代码 作用
console_usart.h 使用串口初始化、发送和接收回调注册接口。
shell.h 使用 Letter Shell 的Shell 结构体和相关函数。
static Shell shell 定义一个 Shell 实例，保存当前命令行状态、读写接口和命令表信息。
static char shell_buffer[512] Shell 的命令行编辑缓冲区。用户每输入一个字符，Shell 会将其保存到这里。
board_lowlevel_init() 由app/board.c 实现，用于开启 GPIOA 与 USART1 时钟。
volatile uint8_t rx_data 保存串口中断收到的一个字节。volatile 告诉编译器该变量会被中断异步修改。

shell 和 shell_buffer 推荐定义为静态对象，使其不占用主函数栈，并保证整个系统运行期间始终有效。

3.2 串口接收回调

USART1 收到数据后会进入中断，在 driver/console/console_usart.c 的 USART1_IRQHandler() 中调用已注册的回调。main.c 注册的回调如下：

static void usart_rx_handle(uint8_t data)
{
    rx_data = data;
}

执行流程是：

  1. 串口助手发送一个字符，例如 a。
  2. USART1 接收中断触发。
  3. USART1_IRQHandler() 读取硬件接收寄存器中的 a。
  4. 中断处理函数调用 usart_rx_handle('a')。
  5. usart_rx_handle() 将字符保存到 rx_data。
  6. 主循环中的 Shell 再从 rx_data 取走该字符。

当前实现只保存一个字符，因此适合人工逐字输入命令。快速粘贴较长命令时，新的字符可能覆盖尚未处理的旧字符；此时应改用环形缓冲区。

3.3 Shell 输入接口

Shell 不会直接读取 USART 寄存器，而是通过 shell.read 调用下面的函数：

static signed short _shell_read(char *data, unsigned short len)
{
    if (rx_data != 0)
    {
        *data = rx_data;
        rx_data = 0;
        return 1;
    }
    return 0;
}

这段代码的含义是：

  1. 判断 rx_data 是否有待处理字符。
  2. 有数据时，将字符写入 Shell 提供的 data 地址。
  3. 将 rx_data 清零，表示该字符已经被取走。
  4. 返回 1，表示本次成功读取一个字节。
  5. 没有数据时返回 0，让 shellTask() 立即返回，不能在此处阻塞等待。

len 是 Shell 希望读取的最大长度。当前工程的接收缓存每次只保存一个字符，因此实际只读取一个字节。

3.4 Shell 输出接口

Shell 需要向终端打印提示符、回显输入和命令结果时，会通过 shell.write 调用下面的函数：

static signed short _shell_write(char *data, unsigned short len)
{
    for (unsigned short i = 0; i < len; i++)
    {
        usart_send((uint8_t)data[i]);
    }
    return 0;
}

执行过程为：

  1. Shell 将待输出内容的首地址和长度传入 _shell_write()。
  2. 函数逐个取出字符。
  3. 每个字符调用 usart_send()，由 USART1 发送到串口助手。
  4. 因此 shellPrint()、shellWriteString()、帮助信息和命令提示符都会显示在串口助手中。

3.5 main() 初始化顺序

main() 中的实际执行顺序如下：

int main(void)
{
    board_lowlevel_init();
    usart_init();
    usart_recv_callback_register(usart_rx_handle);

    shell.read = _shell_read;
    shell.write = _shell_write;
    shellInit(&shell, shell_buffer, sizeof(shell_buffer));

    while (1)
    {
        shellTask(&shell);
    }
}

必须按此顺序执行：

  1. board_lowlevel_init()：开启 USART1 使用的 GPIOA、USART1 时钟，并设置 NVIC 优先级分组。
  2. usart_init()：配置 PA9 为 USART1 发送引脚、PA10 为 USART1 接收引脚，配置波特率为 115200，并开启 USART1 接收中断。
  3. usart_recv_callback_register(usart_rx_handle)：注册接收回调。完成这一步后，接收到的字符才能传递给 rx_data。
  4. shell.read = _shell_read：指定 Shell 从哪里读取用户输入。
  5. shell.write = _shell_write：指定 Shell 将输出发送到哪里。
  6. shellInit(&shell, shell_buffer, sizeof(shell_buffer))：初始化 Shell 内部状态、绑定命令行缓冲区，并读取 shell_cmd_list.c 中的命令表。
  7. while (1)：持续调用 shellTask(&shell)，让 Shell 处理串口输入。

如果漏掉第 4 步或第 5 步，Shell 没有输入或输出通道；如果漏掉第 6 步，Shell 内部状态未初始化；如果漏掉第 7 步，串口收到的数据不会被解析为命令。

3.6 从输入到执行命令的数据流

以输入 add 1 2 并按下回车为例：

串口助手
  -> USART1 接收中断
  -> usart_rx_handle()
  -> rx_data
  -> _shell_read()
  -> shellTask()
  -> Shell 命令解析
  -> shell_cmd_list.c 中的 add 命令
  -> cmd_add()
  -> _shell_write()
  -> 串口助手显示结果

shellTask() 每次最多处理已经接收到的数据。依次输入 a、d、d、空格、1、空格、2、回车后，Shell 会在回车时将整行拆分为参数数组，并调用注册的 cmd_add(argc, argv) 函数。

4. 初始化流程

当前裸机工程的初始化顺序如下：

board_lowlevel_init();
usart_init();
usart_recv_callback_register(usart_rx_handle);

shell.read = _shell_read;
shell.write = _shell_write;
shellInit(&shell, shell_buffer, sizeof(shell_buffer));

各步骤说明：

  1. board_lowlevel_init() 开启 GPIOA、USART1 时钟并设置中断优先级分组。
  2. usart_init() 配置 USART1 引脚、波特率和接收中断。
  3. usart_recv_callback_register() 注册串口接收回调；每收到一个字节，回调会保存该字节。
  4. 为 shell.read 和 shell.write 分别绑定输入、输出函数。
  5. shellInit() 初始化 Shell，第二个参数为命令行缓冲区，第三个参数为缓冲区大小。

shell_buffer 当前大小为 512 字节，单条命令及其参数总长度不要超过该值。

5. 主循环运行方式

裸机模式下，在主循环中持续调用 shellTask()：

while (1)
{
    shellTask(&shell);
}

shellTask() 会调用 shell.read 获取串口数据，完成编辑、历史命令、补全和命令解析。当前 SHELL_TASK_WHILE 配置为 0，因此必须在主循环中反复调用它。

6. 串口读写接口

Shell 不直接依赖硬件串口，而是通过两个回调函数通信：

static signed short _shell_read(char *data, unsigned short len);
static signed short _shell_write(char *data, unsigned short len);

6.1 输入接口

_shell_read() 从串口接收缓存中取出数据并写入 data。有数据时返回实际读取字节数，无数据时返回 0，不能阻塞等待数据。

当前工程使用单字节变量保存中断接收的数据，适合手动输入命令。若需要接收大量连续数据，应改为环形缓冲区，避免后到的数据覆盖前一个未处理的字符。

6.2 输出接口

_shell_write() 将 Shell 输出内容逐字节调用 usart_send() 发送到串口。命令函数输出内容时，优先使用 Shell 自身的输出函数：

shellPrint(shellGetCurrent(), "value: %d\r\n", value);
shellWriteString(shellGetCurrent(), "done\r\n");

不建议在命令函数中直接使用 printf()，否则输出重定向方式可能与 Shell 串口不一致。

7. 已注册命令

连接串口后输入 help 可查看命令列表。当前用户命令如下：

命令 示例 说明
helloworld helloworld 123 tpj 输出问候语并打印参数数组。
add add 12 30 计算两个整数之和。
help help add 查看全部命令或指定命令的帮助。
clear clear 清空终端显示。

命令以空格分隔参数。以 helloworld 123 tpj 为例：

参数 内容
argv[0] helloworld
argv[1] 123
argv[2] tpj

8. 新增一个命令

本工程的 SHELL_USING_CMD_EXPORT 配置为 0，因此采用命令表注册方式。新增命令包含以下三步。

8.1 编写命令函数

在 app/commands 下创建源文件，例如 example.c：

#include "shell.h"

int cmd_example(int argc, char *argv[])
{
    if (argc != 2)
    {
        shellPrint(shellGetCurrent(), "usage: example <value>\r\n");
        return -1;
    }

    shellPrint(shellGetCurrent(), "value: %s\r\n", argv[1]);
    return 0;
}

读取 argv[1] 等参数前必须先检查 argc，防止参数不足导致越界访问。

8.2 在命令表中声明函数

打开 third_lib/lettershell/shell_cmd_list.c，在已有用户命令声明后添加：

extern int cmd_example(int argc, char *argv[]);

8.3 注册命令

在同一文件的 shellCommandList[] 数组末尾添加：

SHELL_CMD_ITEM(
    SHELL_CMD_PERMISSION(0) |
    SHELL_CMD_TYPE(SHELL_TYPE_CMD_MAIN) |
    SHELL_CMD_DISABLE_RETURN,
    example,
    cmd_example,
    example command),

最后将 example.c 加入 Keil 工程的 app/commands 分组，重新编译下载。串口输入 example test 即可执行。

9. 常用配置

配置文件为 third_lib/lettershell/shell_cfg.h。

配置项 当前值 作用
SHELL_TASK_WHILE 0 裸机模式，由主循环调用shellTask()。
SHELL_USING_CMD_EXPORT 0 使用shell_cmd_list.c 命令表注册命令。
SHELL_HISTORY_MAX_NUMBER 5 保存最近 5 条历史命令。
SHELL_PRINT_BUFFER 512 格式化输出缓冲区大小。
SHELL_ENTER_LF 1 支持换行符结束命令。
SHELL_ENTER_CR 1 支持回车符结束命令。

当前工程建议保持 SHELL_USING_CMD_EXPORT 为 0。切换为 1 后需要处理 Keil 链接器的 shellCommand 段，不能只修改配置宏。

10. RTOS 使用方式

使用 FreeRTOS 等系统时，可将 SHELL_TASK_WHILE 设置为 1，然后将 Shell 放入独立任务：

shell.read = _shell_read;
shell.write = _shell_write;
shellInit(&shell, shell_buffer, sizeof(shell_buffer));

xTaskCreate(shellTask, "shell", 256, &shell, 5, 0);

启用后 shellTask() 自身会循环执行。若串口接收中断和 Shell 任务存在并发访问，应同时实现 SHELL_USING_LOCK 相关配置，并使用适合 RTOS 的接收队列或环形缓冲区。

11. 常见问题

输入命令后没有反应

检查串口助手波特率是否为 115200，检查发送结束符是否包含回车或换行，并确认主循环仍在调用 shellTask()。

help 中没有新命令

检查命令函数是否已声明并加入 shellCommandList[]，并确认新增的 .c 文件已加入 Keil 工程后重新编译。

快速粘贴命令时出现字符丢失

当前单字节接收缓存可能被覆盖。应将 rx_data 改为中断写入、主循环读取的环形缓冲区。
