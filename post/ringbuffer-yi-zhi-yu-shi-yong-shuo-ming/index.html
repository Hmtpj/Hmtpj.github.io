RingBuffer 移植与使用说明

1. 文档目的

本文说明本工程中 RingBuffer 环形缓冲区的移植方式、接口用法和在 STM32F407 串口接收场景中的集成流程。当前实现用于解决以下问题：串口接收中断到达速度高于 Letter Shell 命令处理速度时，不能只用单个变量暂存数据，否则后到的数据会覆盖先到的数据。

当前数据流如下：

串口终端 -> USART1 接收中断 -> usart_rx_handle() -> RingBuffer
                                                    -> 主循环 -> shellHandler()

中断负责快速接收并入队，主循环负责出队和执行 Shell 输入处理。这样可缩短中断处理时间，降低连续输入时的数据丢失概率。

4. RingBuffer 原理

环形缓冲区由用户提供的一段连续内存和三个状态量组成：

成员 含义
head 下一个读取位置
tail 下一个写入位置
Length 当前已存储的有效字节数
array_addr 外部数据数组首地址
max_Length 缓冲区总容量

写入数据时，从 tail 位置开始写入并推进 tail；读取数据时，从 head 位置开始读取并推进 head。当指针到达数组末尾时回到数组起始位置，因此读写可以循环进行。

本实现用 Length 区分空和满：

状态 判定条件
空 Length == 0
满 Length == max_Length
可用空间 max_Length - Length

因此，容量为 128 字节的数组可以保存完整的 128 字节，不需要预留一个空槽。

5. 接口说明

ringbuffer.h 中的状态码如下：

/* 操作成功 */
#define RING_BUFFER_SUCCESS 0x01

/* 操作失败 */
#define RING_BUFFER_ERROR   0x00
接口 作用 失败条件
RB_Init 绑定外部数组并清空逻辑状态 容量小于 2，或容量为0xFFFFFFFF
RB_Write_Byte 写入一个字节 缓冲区已满
RB_Write_String 连续写入指定长度的数据 剩余空间不足
RB_Read_Byte 读取并移除一个字节 缓冲区为空
RB_Read_String 读取并移除指定长度的数据 有效数据不足
RB_Delete 从读取端丢弃指定长度的数据 要删除的长度大于有效数据长度
RB_Get_Length 获取当前有效数据长度 无
RB_Get_FreeSize 获取剩余可写空间 无

5.1 初始化

外部数组必须在 RingBuffer 使用期间持续有效。推荐用静态数组，避免函数返回后内存失效。

#include <stdint.h>
#include "ringbuffer.h"

/* 定义实际的数据存储空间 */
static uint8_t rx_buffer[128];

/* 定义环形缓冲区控制块 */
static ring_buffer rx_ringbuffer;

void ringbuffer_init_example(void)
{
    /* 绑定存储数组并清空读写状态 */
    if (RB_Init(&rx_ringbuffer, rx_buffer, sizeof(rx_buffer)) != RING_BUFFER_SUCCESS)
    {
        /* 初始化失败时不得继续使用该缓冲区 */
        while (1)
        {
        }
    }
}

5.2 单字节写入和读取

单字节接口适合串口中断等逐字节到达的场景。

uint8_t input = 'A';
uint8_t output;

/* 有空间时写入一个字节 */
if (RB_Write_Byte(&rx_ringbuffer, input) == RING_BUFFER_SUCCESS)
{
    /* 写入成功 */
}

/* 有数据时读取一个字节；读取后该字节从缓冲区移除 */
if (RB_Read_Byte(&rx_ringbuffer, &output) == RING_BUFFER_SUCCESS)
{
    /* output 的值为 'A' */
}

5.3 批量写入和读取

批量接口内部使用 memcpy。数据跨越数组尾部时，函数会自动拆成两段复制，调用方不需要处理回绕。

uint8_t tx_data[] = {1, 2, 3, 4};
uint8_t rx_data[4];

/* 只有剩余空间可容纳全部数据时才写入 */
if (RB_Write_String(&rx_ringbuffer, tx_data, sizeof(tx_data)) == RING_BUFFER_SUCCESS)
{
    /* 四个字节已按顺序写入 */
}

/* 只有有效数据不少于请求长度时才读取 */
if (RB_Read_String(&rx_ringbuffer, rx_data, sizeof(rx_data)) == RING_BUFFER_SUCCESS)
{
    /* rx_data 依次得到 1、2、3、4 */
}

5.4 丢弃已接收数据

当协议出错或需要跳过无效帧头时，可从读取端删除指定数量的数据。

/* 丢弃最早进入缓冲区的两个字节 */
if (RB_Delete(&rx_ringbuffer, 2) != RING_BUFFER_SUCCESS)
{
    /* 当前有效数据不足两个字节，未执行删除 */
}

6. 当前 STM32F407 移植步骤

以下步骤对应当前工程，移植到新建 STM32F4 标准库工程时可按同样顺序完成。

6.1 加入 RingBuffer 源文件

将下列文件复制到目标工程的第三方组件目录：

third_lib/ringbuffer/ringbuffer.c
third_lib/ringbuffer/ringbuffer.h

在 Keil 的工程分组中加入 ringbuffer.c，并在 C/C++ 的 Include Paths 中加入 third_lib/ringbuffer。当前工程的头文件路径已包含该目录。

6.2 加入串口驱动

当前串口驱动位于 driver/console，其职责是完成硬件初始化和将接收到的字节交给已注册回调。

初始化顺序为：

  1. board_lowlevel_init() 配置 NVIC 优先级分组，并打开 GPIOA 与 USART1 时钟。
  2. usart_init() 将 PA9、PA10 配置为复用功能，设置 USART1 参数并使能 RXNE 接收中断。
  3. usart_recv_callback_register() 注册接收回调。

当前驱动关键行为如下：

void USART1_IRQHandler(void)
{
    /* 判断是否由接收数据寄存器非空中断触发 */
    if (USART_GetITStatus(USART1, USART_IT_RXNE))
    {
        /* 读取数据寄存器，获得本次接收的一个字节 */
        uint8_t data = USART_ReceiveData(USART1);

        /* 将字节交给应用层注册的接收处理函数 */
        if (usart_rx_callback)
        {
            usart_rx_callback(data);
        }

        /* 清除本次中断的挂起状态 */
        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}

移植到其他串口时，需要同步替换外设时钟、GPIO 端口和引脚、复用功能编号、IRQ 名称，以及 USARTx 实例。例如使用 USART2 时，通常应调整为对应的 APB1 时钟和 USART2_IRQHandler。

6.3 在应用层建立接收队列

app/main.c 定义了数据数组和 RingBuffer 控制块：

/* 串口接收数据的实际存储空间 */
static uint8_t rx_buffer[128];

/* 串口接收队列的控制块 */
static ring_buffer rx_rb_handle;

接收回调运行在 USART1 中断上下文中。当前逻辑在空间足够时写入；满时直接丢弃新到字节。

static void usart_rx_handle(uint8_t data)
{
    /* 缓冲区未满时保存新到的串口字节 */
    if (RB_Get_FreeSize(&rx_rb_handle) > 0)
    {
        RB_Write_Byte(&rx_rb_handle, data);
    }

    /* 缓冲区满时丢弃本字节，避免覆盖尚未处理的数据 */
}

主循环在非中断上下文中持续检查并读取数据，再传入 shellHandler()：

while (1)
{
    /* 缓冲区有数据时取出一个字节 */
    if (RB_Get_Length(&rx_rb_handle) > 0)
    {
        RB_Read_Byte(&rx_rb_handle, &read_data);

        /* 将字节送入 Letter Shell 的命令解析器 */
        shellHandler(&shell, read_data);
    }
}

6.4 初始化顺序

main() 中的关键初始化顺序不能颠倒：应先初始化底层时钟和串口，再注册回调并初始化 RingBuffer，最后初始化 Shell。

int main(void)
{
    /* 打开 GPIOA、USART1 时钟并设置中断优先级分组 */
    board_lowlevel_init();

    /* 初始化 USART1 硬件和接收中断 */
    usart_init();

    /* 注册中断接收后的应用层处理函数 */
    usart_recv_callback_register(usart_rx_handle);

    /* 初始化串口接收环形缓冲区 */
    RB_Init(&rx_rb_handle, rx_buffer, sizeof(rx_buffer));

    /* 配置 Shell 的发送接口并初始化 Shell */
    shell.write = _shell_write;
    shellInit(&shell, shell_buffer, sizeof(shell_buffer));

    while (1)
    {
        /* 主循环按需读取 RingBuffer 并调用 shellHandler() */
    }
}

实际工程中，更稳妥的写法是在 RB_Init() 成功后再开启 RXNE 中断或注册回调。这样可以排除初始化窗口内发生接收中断、但缓冲区尚未准备完成的风险。

7. Letter Shell 关联配置

本工程的 third_lib/lettershell/shell_cfg.h 中，SHELL_USING_CMD_EXPORT 为 0，因此 Shell 命令使用静态命令表方式管理：

  1. 在 app/commands 中实现命令函数，例如 cmd_helloworld()、cmd_add()。
  2. 在 third_lib/lettershell/shell_cmd_list.c 中声明命令函数。
  3. 在 shellCommandList[] 中增加 SHELL_CMD_ITEM(...)。

串口接收与命令注册相互独立：RingBuffer 只保证输入字节按先进先出顺序交给 shellHandler()；命令表决定 Shell 收到完整命令行后执行哪个命令。

可在串口终端中输入以下命令进行联调：

help
helloworld
helloworld 123 tpj hm
add 12 30

终端需设置为 115200 波特率、8 数据位、无校验、1 停止位、无流控。按回车后 Shell 会执行命令；当前配置同时接受回车符 CR 和换行符 LF。

8. 容量选择

缓冲区容量应根据最大突发数据量和主循环的最长处理阻塞时间选择。可使用下面的估算：

最小容量 >= 接收速率（字节每秒） × 最大处理延迟（秒） + 安全余量

以 115200 波特率、8N1 为例，每个字节约占 10 个串行位，理论最大接收速率约为 11520 字节每秒。若主循环最长可能 10 ms 未处理接收数据，则至少需要：

11520 × 0.01 = 115.2 字节

当前 128 字节缓冲区仅能覆盖约 11 ms 的满速连续输入，安全余量有限。若主循环中将加入耗时操作、打印操作、Flash 写入或协议解析，应增大 rx_buffer，例如 256 或 512 字节，并评估 SRAM 占用。

9. 并发与中断注意事项

当前用法是“中断写入，主循环读取”。ring_buffer 的成员为普通变量，库本身不提供原子操作、临界区或锁，因此需注意以下边界：

  1. head、tail 和 Length 可能同时被中断和主循环访问。
  2. Cortex-M4 对对齐的 32 位单次读写通常是原子的，但“先查询长度再读写”属于多个操作，不是完整原子事务。
  3. 当前应用数据量较小、主循环操作很短，通常可用于教学和轻量串口交互；更高吞吐量或更严格可靠性要求下，应加入同步保护。
  4. 不要在两个不同中断或多个任务中同时写同一个 RingBuffer，也不要让多个消费者同时读取同一个 RingBuffer。

可选改进措施：

场景 建议
裸机且需要严格一致性 对查询加操作的组合使用短临界区保护
使用 FreeRTOS 用临界区、互斥机制或专用消息队列保护访问
高速连续串口数据 使用 DMA 循环接收，并在半传输/全传输事件中批量入队或直接解析
缓冲区溢出需追踪 增加溢出计数器和错误上报接口
不允许丢弃新数据 明确改用覆盖旧数据策略，或采用流控/协议确认机制

10. 当前实现的限制

使用或二次移植前应了解以下限制：

  1. RB_Init()、读写和查询接口未检查空指针，调用方必须传入有效地址。
  2. RB_Write_String() 与 RB_Read_String() 的数据指针必须有效，且缓冲区大小由调用方保证。
  3. 写入空间不足时，批量写入不会写入部分数据；单字节写入会直接失败。
  4. 当前串口回调在缓冲区满时静默丢弃新字节，没有统计或提示。
  5. 当前 _shell_write() 使用轮询发送，一个字节发送完成后才发送下一个字节；大量 Shell 输出会占用主循环时间。
  6. ringbuffer.h 使用 uint8_t 和 uint32_t，新工程应确保在包含该文件前或该文件内部可获得 <stdint.h> 定义。建议在头文件中显式包含 <stdint.h>。
  7. RingBuffer 只保存二进制字节，不负责字符串结尾符、帧边界、校验或协议超时处理。

12. 验证建议

12.1 基础功能

  1. 编译 Keil 工程，确认无 ringbuffer.c、头文件路径或串口 IRQ 相关错误。
  2. 下载程序后打开串口终端，使用当前串口参数连接目标板。
  3. 输入 help，确认 Shell 有响应。
  4. 输入 helloworld 123 tpj hm，确认参数按顺序输出。
  5. 输入 add 12 30，确认得到正确加法结果。

14. 总结

本工程将 RingBuffer 放在 USART1 接收中断和 Letter Shell 主循环之间，实现了串口字节的先进先出缓存。移植的关键不是只复制 ringbuffer.c 与 ringbuffer.h，还需要正确配置源文件、头文件路径、串口硬件、中断回调、缓存容量和并发访问策略。对于低速命令交互，当前 128 字节方案可直接使用；对于高速、长时间阻塞或多任务系统，应进一步完善溢出统计、临界区保护和 DMA 接收机制。
