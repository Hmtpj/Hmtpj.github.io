TLSF 内存管理使用说明

tlsf的断言__aeabi_assert是失败要考虑怎么补充

1. 作用

TLSF（Two Level Segregated Fit）是适合嵌入式系统的动态内存分配器。它从一块预先提供的连续 RAM 中分配和回收内存，不依赖 C 库的 malloc 和 free。

本工程已移植 TLSF 3.1，源码位于：

  • third_lib/tlsf/tlsf.c
  • third_lib/tlsf/tlsf.h

当前实现使用一块 64 KiB 的静态数组作为内存池，内存池管理与业务代码隔离在 app/mem_mgmt.c 中。

2. 当前工程的结构

app/main.c
    └─ init_dynamic_memory_pool()    初始化 TLSF 内存池

app/mem_mgmt.c
    ├─ dyl_mem_pool[64 * 1024]       实际提供给 TLSF 的 64 KiB RAM
    ├─ tlsf                          TLSF 控制句柄，仅本文件可见
    ├─ malloc_dynamic_memory()       分配接口
    └─ free_dynamic_memory()         释放接口

app/commands/mem.c
    └─ cmd_mem                       Shell 分配、释放演示命令

dyl_mem_pool 和 tlsf 都是 static，其他源文件不能直接访问。这能避免业务代码错误地操作内存池或使用未初始化的句柄。

3. 工程初始化

app/main.c 在进入主循环前调用：

/* 初始化动态内存池，必须在任何分配操作之前执行 */
init_dynamic_memory_pool();

实际初始化逻辑位于 app/mem_mgmt.c：

/* 静态数组提供给 TLSF 管理，大小为 64 KiB */
static uint8_t dyl_mem_pool[64 * 1024];

/* TLSF 控制句柄，仅当前源文件使用 */
static tlsf_t tlsf;

/* 创建 TLSF 控制结构，并将静态数组同时作为首个内存池 */
void init_dynamic_memory_pool(void)
{
    tlsf = tlsf_create_with_pool(dyl_mem_pool, sizeof(dyl_mem_pool));

    /* 创建失败时停止运行，防止后续继续使用无效句柄 */
    if (tlsf == NULL)
    {
        while (1)
        {
        }
    }
}

tlsf_create_with_pool 会在 dyl_mem_pool 开头放置 TLSF 控制信息，剩余区域才可用于动态分配。因此可分配总量小于 64 KiB，且每次分配还会有少量块管理开销。

4. 业务代码的标准用法

业务代码包含 main.h 后，调用工程封装接口即可：

#include "main.h"

void example(void)
{
    uint8_t *buffer;

    /* 从 TLSF 内存池申请 128 字节 */
    buffer = (uint8_t *)malloc_dynamic_memory(128);
    if (buffer == NULL)
    {
        /* 申请失败时执行降级处理，不能继续访问 buffer */
        return;
    }

    /* 此处使用 buffer 指向的 128 字节有效区域 */

    /* 使用结束后原样释放，并避免再次使用 buffer */
    free_dynamic_memory(buffer);
    buffer = NULL;
}

分配接口为：

void *malloc_dynamic_memory(size_t bytes);
  • bytes：申请的字节数，应大于 0。
  • 成功：返回可读写内存的首地址。
  • 失败：返回 NULL，常见原因是剩余空间不足或碎片无法满足请求。

释放接口为：

void free_dynamic_memory(void *ptr);
  • ptr 必须是 malloc_dynamic_memory 返回且尚未释放的地址。
  • 传入 NULL 是安全的，TLSF 不执行操作。
  • 一块内存只能释放一次；释放后不得继续读写，也不能再次释放。

4.2 原生 TLSF 接口直接使用

如果移植到其他工程，或需要自行管理多个内存池，可直接调用 tlsf.h 提供的原生接口。下面是单内存池的最小完整用法：

#include <stdint.h>
#include "tlsf.h"

/* 静态数组作为 TLSF 的控制区和首个内存池，生命周期覆盖整个程序 */
static uint8_t tlsf_memory[64 * 1024];

/* 保存创建成功后的 TLSF 句柄 */
static tlsf_t tlsf_handle;

/* 在任何动态内存操作前执行一次初始化 */
static int tlsf_memory_init(void)
{
    /* 创建控制结构，并把 tlsf_memory 加入为首个内存池 */
    tlsf_handle = tlsf_create_with_pool(tlsf_memory, sizeof(tlsf_memory));

    /* 返回初始化结果，调用方必须检查 */
    return (tlsf_handle != NULL) ? 0 : -1;
}

void example(void)
{
    uint8_t *buffer;

    /* 从 tlsf_handle 对应的内存池申请 128 字节 */
    buffer = (uint8_t *)tlsf_malloc(tlsf_handle, 128);
    if (buffer == NULL)
    {
        /* 内存不足时不能访问 buffer */
        return;
    }

    /* 此处只能访问 buffer 的 0 至 127 字节 */

    /* 必须使用同一个 tlsf_handle 释放该内存 */
    tlsf_free(tlsf_handle, buffer);
    buffer = NULL;
}

调用顺序必须是：tlsf_create_with_pool -> tlsf_malloc / tlsf_memalign / tlsf_realloc -> tlsf_free。初始化只执行一次；应用运行期间不能再次对同一块内存重复创建 TLSF。

原生接口和当前工程封装接口不能交叉配对：

  • malloc_dynamic_memory 返回的指针必须用 free_dynamic_memory 释放。
  • tlsf_malloc(tlsf_handle, ...) 返回的指针必须用 tlsf_free(tlsf_handle, ...) 释放。
  • 禁止用一个 TLSF 句柄释放另一个 TLSF 句柄申请的指针，也禁止用 C 库的 free 释放 TLSF 指针。

5. Shell 演示命令

app/commands/mem.c 提供 mem 命令。输入：

mem 128

命令会申请 128 字节，打印结果和地址，然后立即释放该内存。它只用于验证基本分配流程，不能用于观察长期内存占用，因为命令结束前已释放。

当前命令直接使用 atoi(argv[1])，调用时必须提供正整数参数。缺少参数、传入负数或非数字字符串可能产生非预期结果，业务代码应先检查参数数量和取值范围。

6. 原生 TLSF 接口

除工程封装外，tlsf.h 还提供下列接口。扩展功能时可使用，但必须统一管理 tlsf_t 句柄，并避免和现有封装混用不受控的内存池。

接口 用途 注意事项
tlsf_create(mem) 在指定内存中创建控制结构 仅创建控制结构，之后需调用tlsf_add_pool 添加内存池。
tlsf_create_with_pool(mem, bytes) 创建控制结构并添加首个内存池 当前工程使用此接口。
tlsf_add_pool(tlsf, mem, bytes) 增加一块独立内存池 内存首地址必须满足tlsf_align_size() 对齐要求。
tlsf_remove_pool(tlsf, pool) 移除一个内存池 移除前必须释放该池内所有已分配块。
tlsf_malloc(tlsf, bytes) 分配内存 返回值必须判空。
tlsf_memalign(tlsf, align, bytes) 按指定边界对齐分配 align 必须是 2 的整数次幂。
tlsf_realloc(tlsf, ptr, size) 调整已分配内存大小 可能返回新地址，必须用临时指针接收。
tlsf_free(tlsf, ptr) 释放内存 ptr 必须来自同一个 TLSF 句柄。
tlsf_check(tlsf) 检查所有空闲链表一致性 返回非 0 表示发现内部结构异常。
tlsf_check_pool(pool) 检查一个内存池的物理块连续性 适合定位越界写或重复释放后的损坏。

6.1 对齐分配示例

DMA、缓存或外设访问可能要求缓冲区按特定边界对齐。例如申请 256 字节对齐的 1024 字节缓冲区：

/* 对齐值为 2 的整数次幂，满足 DMA 缓冲区对齐要求 */
void *dma_buffer = tlsf_memalign(tlsf, 256, 1024);

/* 申请成功后按普通 TLSF 内存释放 */
if (dma_buffer != NULL)
{
    tlsf_free(tlsf, dma_buffer);
}

当前工程的 tlsf 是 mem_mgmt.c 的私有变量，因此若要开放此功能，建议新增 malloc_dynamic_memory_aligned 封装函数，而不是在其他文件定义另一个同名或重复的句柄。

6.2 realloc 的正确用法

tlsf_realloc 可能原地扩展，也可能申请新块、复制原数据并释放旧块。不能直接覆盖原指针，否则申请失败时会丢失旧地址。

/* 临时指针用于保留 realloc 失败时的原始内存地址 */
void *new_buffer = tlsf_realloc(tlsf, old_buffer, new_size);

if (new_buffer != NULL)
{
    old_buffer = new_buffer;
}
else
{
    /* old_buffer 仍有效，可继续使用或在合适时机释放 */
}

7. 内存池规划要求

7.1 内存池必须长期有效

内存池不能定义为初始化函数的局部数组，因为函数返回后局部变量失效。应放在静态区、全局区或一段专用 RAM 区。本工程的 static uint8_t dyl_mem_pool[64 * 1024] 符合该要求。

7.2 内存池大小

TLSF 会占用控制结构和块头，内存池实际可用容量小于数组容量。可通过下列接口了解开销：

/* 查询 TLSF 控制结构、内存池块头和单次分配块头的开销 */
size_t control_bytes = tlsf_size();
size_t pool_overhead = tlsf_pool_overhead();
size_t alloc_overhead = tlsf_alloc_overhead();

不要以为 64 KiB 内存池一定可以分配一个完整的 64 KiB 块；应预留管理开销，并为其他同时存在的动态对象留出空间。

7.3 对齐

TLSF 在本 32 位 STM32 工程中通常按 4 字节对齐。不要硬编码该数值，使用下列接口获取实际要求：

/* 查询当前 TLSF 版本的最小对齐字节数 */
size_t align_bytes = tlsf_align_size();

静态数组通常自然满足对齐；如果改为链接脚本分配、外部 SRAM 或自定义地址，必须确认首地址满足该对齐要求。

8. 中断与多任务注意事项

当前 TLSF 源码本身不带锁，tlsf_malloc、tlsf_free、tlsf_realloc 和内存池增删不能在不同执行上下文中并发调用。

  • 裸机：主循环使用 TLSF 时，ISR 中不要调用 TLSF 分配或释放。
  • RTOS：多个任务需要调用时，用互斥锁保护所有 TLSF 操作。
  • 中断：中断服务函数只传递事件、数据或通知任务；由任务统一分配和释放内存。
  • 禁止在持有互斥锁时调用会再次触发 TLSF 的未知回调，防止死锁。

9. 断言与故障定位

TLSF 源码默认使用 assert 检查内部不变量。在 ARMCC/Keil 精简运行库配置下，可能出现：

Undefined symbol __aeabi_assert (referred from tlsf.o)

本工程已在 app/main.c 中提供 __aeabi_assert：

/* ARM EABI 断言失败处理函数 */
void __aeabi_assert(const char *expr, const char *file, int line)
{
    /* 避免未使用参数产生编译警告 */
    (void)expr;
    (void)file;
    (void)line;

    /* 断言失败后停止运行，便于调试定位问题 */
    while (1)
    {
    }
}

该函数只能定义一次，不能加 static。调试时在函数入口或死循环处设置断点，查看 expr、file、line 即可定位断言位置。断言被触发通常意味着：重复释放、释放非法地址、越界写、内存池被破坏，或对齐参数错误。

还可在关键测试流程后检查：

/* 返回非 0 时说明 TLSF 内部结构已损坏 */
if (tlsf_check(tlsf) != 0)
{
    /* 在此处设置断点定位首次发现异常的位置 */
    while (1)
    {
    }
}

由于当前 tlsf 未对外暴露，若要在业务代码中调用检查接口，应在 mem_mgmt.c 增加统一的检查封装函数。

10. 重写malloc和free更加方便使用

void *malloc(size_t size)
{
    return malloc_dynamic_memory(size);
}
void free(void *ptr)
{
    free_dynamic_memory(ptr);
}
